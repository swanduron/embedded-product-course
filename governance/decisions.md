| ID | 课程级决策 | 理由/影响 |
|---|---|---|
| D-001 | 产品需求先行，技术由行为和约束推导 | 避免外设细节淹没项目目标 |
| D-002 | 14 章、4 阶段；长期工程不断迭代 | 避免先外设后 RTOS 的割裂与遗忘 |

| D-004 | 原理 + 工程实现 + 故障实验 + 独立迁移练习 | 避免只会 include、只能显示静态内容 |
| D-005 | 统一故障管理贯穿全书，安全路径需硬件边界 | 重视失效传播、恢复与验证 |
| D-006 | 桌面环境终端为贯穿产品；三页面 SSD1306 是候选阶段 UI，LVGL 为后续 GUI 方案 | 连接驱动、界面、数据模型与产品需求 |
| D-007 | 核心应用逻辑不直接依赖特定 MCU SDK 头文件 | 增强可测试性和跨平台复用 |
| D-008 | 简单状态机、Superloop、RTOS 都是可选工具 | 按需求选型，避免架构形式主义 |
| D-009 | 从原型 P0 走到工程样机 P1 与小批量验证 P2 | 强化制造、测试、交付能力 |
| D-010 | Markdown/源码为权威内容源，HTML 为离线阅读及交互形式 | 兼顾 Agent 协作、审核和教学体验 |
| D-011 | 讨论的新想法经 CCP 审批才能进入发布基线 | 避免多 Agent 漂移、无限扩课 |
| D-012 | 运行/理解/修改/迁移分级验收，反馈闭环 | 学过≠学会，不强制按日历推进 |
