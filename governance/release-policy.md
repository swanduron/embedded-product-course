# 内容状态、版本与发布门槛 v1.2

## 三个不同的版本
- **课程架构版本**：14 章总纲及教学契约的修订号（当前目标 v1.1）。
- **章节/实验版本**：每项独立 draft/reviewed/verified，分别记录，不自动视为已发布。
- **HTML/发行包版本**：读者能下载并离线打开的生成物版本。不能因为出现 Markdown 草稿就提前宣称 HTML 已更新。

## 权威格式
Markdown + 实验源码为内容源；HTML 是发布展现。现有 `index.html` 由 `scripts/build_site.py` 将 1.1、1.2 Markdown 写入阅读器模板生成，当前为 `v0.3.0-preview`。必须在 UI 显示自身真实发布版本，不得因为仓库版本较新而误导。

## 章节发布条件
先通过 `editorial-style.md` 的正文连续阅读审查与反提纲化审查，再检查前置满足、术语一致、包含需求/原理/方案/代码/故障/验收/迁移；标记教学假设；示例能重建、验证证据齐全；所有外部链接和 HTML 交互检查；人工审核通过。不满足的部分显式 `draft`。

## 测试证据等级
`CONCEPT` 概念/伪代码；`BUILD` 在指定编译器通过；`UNIT` 单元测试通过；`SIM` PC 仿真通过；`HIL` 实际板级实验通过；`SOAK` 持续运行试验通过。更高等级不自动暗示满足安全认证。每一条证据记录环境、命令、结果、日期、板卡版本（如适用）。

## 发布步骤
1. 锁定版本与变更清单。
2. 检查 Markdown 内容源与章节链接。
3. 生成/同步 HTML，验证目录、交互、离线打开和移动端布局。
4. 检查源码/构建/测试记录。
5. 更新 release-notes、版本号和分发包。
6. 保留上一发布包，便于回滚。

## 当前项目的已知缺口
1.1、1.2 均已进入 HTML 阅读预览，仍为待学习者审阅的正文草稿。阅读器构建、链接、布局和交互检查与应用功能 BUILD/UNIT/SIM、硬件 HIL/SOAK 证据分开记录；不得相互替代。完整应用工程、真实硬件验证与正式分发包/回滚流程仍未完成，不能将此预览当作已审核的完整教材发行版。
