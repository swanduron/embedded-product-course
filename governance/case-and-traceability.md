# 贯穿案例、需求追踪与实验资产 v1.1

## 主线产品
三页面桌面环境仪表（Monitor / History / Settings）。开始时在 PC 上使用模拟数据，逐步引入按钮、编码器、传感器、双 SSD1306、FreeRTOS、LVGL 及最终小批量验证。不是要求三页面小 OLED 直接承担大型 LVGL 的全部交互功能。

## 案例列表
- C-01：三页面 OLED；从显示固定文字→动态数值/曲线→设置与报警→故障/恢复→跨平台。
- C-02：Button Component；从电平采样→消抖→短按/长按/双击→事件与队列→物理板验证。
- C-03：I²C 同地址设备；TCA9548A + 双 SSD1306 → 总线原子操作 → 竞争/超时/恢复。
- C-04：设备状态与统一失效；OFF/ON/FAULT → 故障分类/锁定/复位 → 硬件保护边界。
- C-05：产品化；从通用实验底板到精简专用 PCB、BOM、生产自检、升级、长期运行。

## 需求到产物链
每个需求 `REQ-XXX` 必须在相关章节追踪：产品场景 → 具体可观察行为 → 设计决策/ADR → 模块接口 → 测试 `TEST-XXX` → 证据等级/章节版本。没有相应测试的需求是待验证，不是已完成。

## 工程资产规则
完整、持续演进的源码工程；公共模块放共享目录，平台适配单独维护；chapter tag/commit 对应稳定检查点。不要每章重新复制一套不兼容的 `button.c` 或 I²C HAL。跨章修改接口时，检查调用方及测试。

## SSD1306 与 LVGL 的教学关系
首先学习轻量 display model + renderer，避免应用层充满 `draw_string` 坐标与清屏命令；再让同一数据模型投影到 LVGL 控件。两者共享数据/业务语义，不保证渲染代码零修改。
