# 教材愿景与范围（权威原则）v1.1

## 教材身份
《现代嵌入式产品工程：从产品构想、系统架构到可交付产品》。不是外设 API 合集、单片机型号培训班，也不是只教 AI 生成代码的速成课。核心培养目标：面对陌生产品需求，能把构想转换成可验证的行为、模块接口、实验及可维护的产品方案。

## 学习者起点
- 有 STM32 寄存器/标准库、I²C、SSD1306、OpenWrt 板级适配等零散经历，能让屏幕显示固定文字/图片，却缺少动态数据、三页面 UI、应用模块组织与跨项目复用的训练。
- 对 RTOS 队列、按键消抖、长按、状态机缺少可靠的直觉；不希望再按照几十周外设课程和几十周 RTOS 课程彼此割裂地学习。
- 能设计 PCB、手焊 0603；有 ESP32-WROOM 裸模块，愿意未来增加 RP2040 与显示硬件。
- 学习者背景用于调整教学起点，**不是**对其能力的永久定性；后续应依据真实练习反馈更新。

## 八条不可妥协的教学原则
1. 产品目标 → 可观察行为 → 可测试需求 → 架构与职责 → 技术实现 → 验证与交付；实现反馈可以促使需求更新。
2. 先教为什么，再教 API；每个技术点需解释“不采用会怎样”“何时不值得采用”。
3. 低层原理、现代库的边界和工程用法并讲；不要求重造 Wi-Fi 协议栈、GUI 引擎或完整 RTOS。
4. 永久工程持续演进：组件在后续章节真实复用，不允许章节完结即丢弃。
5. 学会不等于跑通：运行、解释、修改、迁移与验证四级进展分别评价。
6. 每项关键组件有接口契约、正常行为、异常行为、边界条件和可重复测试。
7. 简单问题可用简单循环或状态机；绝不把“RTOS 多任务”或“复杂抽象”本身当工程成熟的证据。
8. 原型成功不是课程完成；必须覆盖制造、生产测试、版本升级、可靠性和成本取舍。

## 范围边界
- 主线：C/CMake/PC 仿真 → ESP32-WROOM → FreeRTOS → LVGL → RP2040 验证 → 产品化。
- 单色 OLED 的轻量 UI 与 LVGL 是不同的实现选择，共享数据模型，不强迫小屏使用 LVGL。
- 软件仿真不能替代真实的电气、时序、内存、可靠性验证；所有安全关键结果必须区分软件模型与硬件保护。
- 不以商业认证或安全合规已经通过作为教材默认结论。

## 典型反例（禁止将其当章节终点）
- `while(1)` 里硬读按键、直接点亮 LED 即宣称掌握输入系统。

- 一次调用 `xQueueSend` 即宣称学会跨任务通信。
- AI 生成代码通过编译即宣称实现正确。
