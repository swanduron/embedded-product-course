# 学习反馈、知识缺口与课程纠偏 v1.1

## 记录原则
记录“具体任务中看不懂哪一步”，不记录笼统的“学生能力差”。反馈用于调整教法，不自动证明课程错误。反馈与教材正文分离，避免未经确认的结论进入正式章节。

## 推荐记录模板
- 时间、章节、实验版本、复现环境
- 目标行为与实际行为
- 卡住类型：`CONCEPT` 不懂原理 / `DESIGN` 不知如何拆模块 / `IMPLEMENT` 看懂但写不出 / `DEBUG` 不知如何诊断 / `TRANSFER` 换需求不会迁移
- 可复现的最小例子、日志/代码位置
- 已尝试解释/实验及结果
- 所需补充：桥接例题、图示、测试、前置知识或 CCP
- 学习者确认的进展等级：L1/L2/L3/L4

## 已知起始学习需求（来自课程设计讨论，待实际教学验证）
- SSD1306：会显示字符和位图；尚未建立动态显示、三页 UI、页面状态与数据模型能力。
- I²C：会接触示例器件，但欠缺从 Datasheet 推导可复用驱动、总线管理、错误处理的连续训练。
- RTOS：队列、任务同步、时序、按键消抖与应用职责关系需要逐步建立，不应直接堆 API。
- 工程组织：希望从需求出发，逐渐理解 `.c/.h`、CMake、组件接口和测试。
- 项目成果：希望不再停留在单机原型，而能形成可验证、可制造、可维护的产品。

## 从反馈到教材改进
单次问题 → 小实验讲解 → 记录结果；同类障碍重复出现或跨章影响 → CCP；批准后补充桥接内容与测试，复审先修。答疑 Agent 不能把个人临时解释静默写回正式教材。
