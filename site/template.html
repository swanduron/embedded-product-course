教材原型 · v0.1
课程定位

从会调用驱动，到能把构想做成产品

不是再学一轮孤立的 GPIO、I²C 或 FreeRTOS API，而是建立一套产品需求驱动、可验证、可迁移的嵌入式工程能力。

产品驱动

所有技术选择都能追溯到明确的需求和验收条件。

原理与工业实现

从底层机制推导模块接口、并发行为和可靠性设计。

一个长期工程

按键、双 OLED、传感器、RTOS、LVGL 不断迭代和复用。

从原型到交付

覆盖架构、测试、故障恢复、PCB 和小批量验证。

目前完成情况

已形成教材阅读器原型、14 章课程路线、教学规范草案及第 1.1 节内容。完整教材正文、工程源码与硬件图纸尚未完成；请勿将此版本视为已验证的正式教程。

这一实验说明什么？

温度是设备模型，当前页是界面状态，传感器是否在线是数据有效性。驱动只需提供显示输出能力，不应决定页面切换、报警规则或采集策略。

硬件平台 · 规划中

可更换 MCU 的实验底板

统一外设底板，独立 ESP32-WROOM 和 RP2040 转接板。第一阶段在 PC 运行，硬件从第 5 章正式引入。

模块器件 / 教学用途
输入按钮、EC11 编码器：消抖和事件
I²CSHT31、MCP23017、TCA9548A、双 SSD1306：总线拓扑与驱动
SPIW25Q 系列 NOR：读写、擦除、超时与持久化
可靠性INA226、MOSFET 小负载、独立看门狗：故障与恢复
扩展RTC、FRAM、RS-485、SD、音频、WS2812：选修实验
主控现有 ESP32-WROOM；RP2040 作跨平台验证

这是设计目标清单，尚未冻结 GPIO、连接器引脚、原理图、电源预算或 BOM；需要依据具体芯片资料校核。

Agent 协作规则

让教材能跨 Agent 延续

每节固定教学闭环

工程需求 → 底层原理 → 设计推导 → 最小实现 → 工业实现 → 故障实验 → 验收 → 独立迁移

三类 Agent 职责

课程讨论：分析新想法，只形成提案；不默认改正式总纲。

章节编写：读取总纲、教学规范、前置章节和实验代码；不能自行修改全局目标。

学习答疑：记录已掌握和卡住的概念；教材缺陷形成修订建议。

正式变更规则

所有新想法先变成 CCP 提案，标记 proposed / accepted / deferred / rejected；只有批准后才修改正式课程文件。源码与章节内容要进行相互验证。

每个实验应提供独立复现步骤，区分“编译成功”“功能通过”“真正掌握”。
